# Who may use the device, and what it may reach

Read before changing sign-in, the device password, the hosts the server answers to, an HTTP client of ours or a download from a typed-in address. These rules were moved out of `AGENTS.md` unchanged; `AGENTS.md` keeps the rules that apply to every change.

- **Who may use the device** (`python/web/access.py`, #36): there is no default credential. A device on the network starts *unclaimed*, logs a one-time **setup code** (also drawn as a **QR code** on the panel's setup page, #491: `{address}/#/claim/<digits>`, `setup_claim_url` in `python/eink-billboard.py`, made by `utils/qr_image.py` with `segno` as whole black and white pixels a module, so the panel has no grey edge to dither; the code is as visible as the text beside it) (and draws it on the panel through `Application.setup_notice`: a page with no expiry, so it holds the panel until the device is claimed, and the **layers are not configured until then**: `Application` keeps their `ConfigureEvent`s and sends them on `SetupDone`, so no track or timer task goes into play mode on a device nobody owns; a replaced code is redrawn, `SetupCodeChanged`), and whoever enters it at `POST /api/access/setup` chooses the password (kept as a salted scrypt hash in the `access` settings, which is not in `DEVICE_SETTINGS`, so no route serves it). `--token` / `EINK_API_TOKEN` stays the script credential and counts as claiming; `--no-auth` keeps a network device open on purpose; `--require-auth` applies the rules on a local bind (the browser tests); `--reset-password` forgets the password. A device bound to `localhost` is open until a password is set. Routes use `require_auth`; `EINK_SETUP_CODE` fixes the code for tests.
- **The server answers only to names it expects** (`python/web/hosts.py`, DNS rebinding): `localhost`, any IP address, this machine's name and `<name>.local`, and `--allow-host` / `EINK_ALLOW_HOSTS`; any other `Host` gets 421 in the error shape, on HTTP and on the telemetry WebSocket. The tests allow `testserver` through the environment (`python/tests/__init__.py`). A failed `POST /api/session` is logged (address and count, never the token) and the client waits longer after each one past three (`SignInThrottle`: 429 with `Retry-After`, no wait on a server thread).
- **An HTTP client of ours is made with `verify=tls_context()`** (`python/task/async_http_worker_pool.py`; `test_tls_context` scans for the rest). The container's OpenSSL 3.5 puts a post-quantum hybrid key exchange group first in the TLS 1.3 handshake, and some hosts (webcomicname.com on Tumblr) answer by dropping the connection: `RemoteProtocolError: Server disconnected without sending a response`, only from the container (the Windows host's older OpenSSL, `curl` and a browser were fine, and TLS 1.2 worked in the container too). The shared context offers P-256 only, which every TLS 1.3 server accepts. A failure that is the same address in one place and not in another is the stack, not the address: compare the TLS version and groups before the headers. **A client names its timeouts**: httpx's default is 5 s for connecting and for each read, which a small board on a slow link or a slow site (Dinosaur Comics, whose picture redirects to another host) does not meet; the shared pool's client is `REQUEST_TIMEOUT` (30 s, connect 15 s), and a client of our own sets one.
- **Every download of an address that is not our own constant goes through the URL guard.** `stream_to_buffer` (images and feeds) is guarded by default and `stream_checked` (`python/utils/url_guard.py`) is the same for any method: the address and every redirect are checked (not this device, not link-local, ...), because the address is typed in a settings page or taken from a feed, an answer or a redirect (found by the OWASP pass, #189). A new download uses one of them; `guarded=False` is for a constant only. The tests' fake internet makes every fake host resolve to a public address; a test of a refusal patches `url_guard._resolve` or uses an address literal. **The connection goes to an address the guard checked** (#477, DNS rebinding): `stream_checked` hands the checked addresses to the request and `PinnedTransport` (`AsyncHttpWorkerPool.make_transport()`, the transport of every client of ours) connects to one of them, keeping the name for `Host`, SNI and the certificate check, so a name that answers differently the second time is not followed. A new client of ours that downloads from a typed-in address takes `transport=AsyncHttpWorkerPool.make_transport()`, not `None`.

## Rules for IDs from URLs and secrets

Moved out of `AGENTS.md` unchanged; `AGENTS.md` keeps the one-line rules.

- **IDs from URLs are untrusted.** Plugin and datasource IDs must come from `cm.enum_plugins()` / `cm.enum_datasources()`; never build a path from a raw URL parameter.
  Validating is not enough for the analyser (or a reader): what builds the path must be **our own value** (the constant from our list, the ID declared in the descriptor), not the URL's string that passed a check. Files served for a URL are resolved with `realpath` and must start with the folder's prefix (see `_file_in_bundle`), which also stops symbolic links.
  Error bodies do not echo the URL's text back. CodeQL's `py/path-injection` alerts are about exactly this; fix the flow, do not dismiss the alert.
- **Secrets.** A schema property with `"writeOnly": true` is masked (`********`) in GET responses and kept when the mask, or nothing, is sent back. Mark any new key/token/password property that way.
